# Kanban Project

## Business Requirements

- A Kanban style Project Management application as a web app
- The web app has 1 board
- The board has fixed 5 columns that can be renamed
- Each card has a title, details, an optional due date, an optional assignee, and zero or more labels
- Full drag-and-drop: cards can be moved between columns and reordered to any position within a column
- Add a new card to a column; delete an existing card
- Clicking a card opens a right-side detail panel (not a modal); the board stays visible
- Labels are a predefined, centrally-managed, color-coded set (not free-form per-card text), creatable and editable from a Labels manager
- Assignment is to a lightweight named person, not a real account — there is no login or password. A "acting as" switcher in the header lets you pick which seeded person you currently are; you can add new people from that switcher
- Search (title/details) and filter (by label, assignee, and due-date status) narrow the board; while a search or filter is active, drag-and-drop is disabled and non-matching cards are hidden, since reordering a partial view against true positions would be ambiguous
- An in-app notification center (bell icon + panel) shows: a card was assigned to you, a card you're assigned to is due within 24 hours, or a card you're assigned to is overdue (skipped for cards in the last column). Notifications persist in the database and are read via polling, not websockets
- The app opens with dummy data populated for the single board (columns, cards, labels, users)
- No archive. No more notification types than the three listed above. No feature creep beyond what's described here

## Technical Details

- **Frontend**: Next.js (App Router), fully client-rendered, in `frontend/`. TanStack Query for data fetching/caching and optimistic drag-and-drop updates. `@dnd-kit` for drag-and-drop. Tailwind CSS for styling, with Radix UI primitives for popovers/menus. The `?card=<id>` URL parameter drives the detail panel so it's deep-linkable
- **Backend**: Express (TypeScript) in `backend/`, with Prisma + SQLite for persistence (file-based, zero external services). Seeded on first migrate via `npm run prisma:seed`
- **API**: a REST API between frontend and backend (not Next.js API routes, not localStorage-only). Every request carries an `X-User-Id` header identifying the acting user — this is the only auth-like mechanism, and it does not gate access, only scopes notifications and assignment self-checks
- **Notifications**: `DUE_SOON`/`OVERDUE` are generated by an in-process interval checker (no cron dependency), idempotent per (card, user, type). `ASSIGNED` is generated inline when a card's assignee changes. The frontend polls every 30 seconds
- Use idiomatic, current versions of libraries as of today
